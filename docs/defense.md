# Пояснительная записка и защита

## О проекте

«Траты» — многопользовательский сервис учёта личных расходов. Пользователь регистрируется, добавляет покупки по категориям, просматривает историю и статистику, выгружает данные. Все этапы семестрового задания реализованы в одной финальной версии.

## Путь HTTP-запроса

1. На сервере Caddy принимает HTTPS, проверяет сертификат и передаёт запрос контейнеру Go по внутренней сети.
2. `net/http.Server` применяет таймауты и ограничения заголовков.
3. Middleware оборачивают запрос в следующем порядке: **logging → recovery → security headers → session → CSRF → ServeMux → requireAuth → handler**. Ответ проходит обёртки в обратном порядке.
4. Сессионное middleware вычисляет HMAC токена из cookie, находит действующую сессию, помещает пользователя в `context.Context`. Клиент не может самостоятельно назначить свой `user_id`.
5. Обработчик разбирает параметры или форму, проверяет данные и вызывает репозиторий. В обработчиках нет SQL.
6. Репозиторий передаёт параметры отдельно от SQL-текста, выполняет запрос и считывает строки через `Scan`.
7. HTML формируется через общий layout и `html/template`, JSON — через `encoding/json`, CSV — через `encoding/csv`.
8. После успешного изменения данных идёт 303 на GET-страницу. Middleware логирования записывает статус и длительность.

`http.ResponseWriter` задаёт заголовки, статус и тело ответа. Первая запись тела без `WriteHeader` подразумевает 200. Если обработчик вообще ничего не записывает, клиент получает пустой ответ с 200. Поэтому коды ошибок задаются до тела.

## Ключевые решения

**Серверный рендеринг.** Для небольшого учебного проекта достаточно Go-шаблонов: формы и список работают даже без JS, отсутствуют сборка фронтенда и второй API для каждого действия. JS используется только для графиков и удобства ввода.

**SQLite.** Файл хранится отдельно от процесса/контейнера. Миграции применяются один раз и в транзакции. WAL улучшает поведение чтения/записи, одно соединение обеспечивает одинаковые PRAGMA. Это разумная схема для небольшого сервиса; при существенном росте нагрузки слой репозитория можно перенести на другую СУБД.

**Целые копейки.** Десятичные суммы сначала разбираются как строка, затем переводятся в `int64`; вычислений денег через float нет. Поэтому 0,10 + 0,20 даёт ровно 0,30. Преобразование в дробные рубли выполняется только для отображения графиков.

**JOIN и агрегации.** Название категории выбирается вместе с расходом одним запросом. Иначе получение категории для каждой строки создало бы проблему N+1: один запрос списка и N дополнительных запросов. `SUM` и `GROUP BY` позволяют получить небольшую сводку вместо передачи всех расходов в Go/браузер.

**Безопасность.** `html/template` экранирует пользовательский HTML; placeholders `?` защищают структуру SQL; обязательный `user_id` предотвращает доступ к чужим записям. Bcrypt замедляет перебор паролей. Сессия имеет срок и серверную инвалидизацию. Если не проверять срок, украденный токен работал бы бесконечно.

**CSRF.** Подписанный случайный токен должен одновременно находиться в cookie и POST-форме. При входе CSRF-cookie обновляется. Cookie имеет HttpOnly, SameSite=Lax и Secure на сервере; дополнительно проверяется Origin.

**Ошибки.** Валидация выполняется независимо от браузера. Некорректная форма возвращает 422 и введённые значения. Запрос чужой записи выглядит как отсутствующая запись (404). SQL-ошибка логируется, но её подробности не попадают пользователю. Искусственная паника проверяется тестом без публикации специального «ломающего» маршрута.

**Экспорт.** CSV содержит только расходы текущего пользователя; фильтры повторяют список. BOM, `;` и десятичная запятая позволяют открыть файл в русской локали Excel. Строки, похожие на формулы, экранируются апострофом.

## Сценарий выступления: 6 минут

### 0:00–0:40 — задача

«Я сделал сервис личных расходов. В нём можно вести свои покупки, фильтровать историю, смотреть распределение по категориям и динамику по месяцам, выгружать таблицу. Все восемь этапов задания собраны в одном приложении».

Открыть главную страницу и кратко показать навигацию.

### 0:40–1:40 — основной сценарий

Зарегистрировать аккаунт, войти, показать пустое состояние. Добавить:

| Сумма | Категория | Описание |
| --- | --- | --- |
| 450,50 | Еда | Обед |
| 85,00 | Транспорт | Проезд |
| 1 200,00 | Образование | Книга по Go |

Редактировать описание одной записи. Открыть подтверждение удаления и отменить. Показать фильтр категории и диапазон дат.

### 1:40–2:30 — статистика и CSV

Открыть статистику, объяснить различие периода круговой диаграммы и года столбчатой. Изменить год на период без записей, показать пустое состояние. Вернуться и скачать CSV через список с фильтром.

### 2:30–3:30 — архитектура

Показать схему из README и папки `internal/handlers`, `internal/repository`, `web/templates`, `migrations`. Проследить один метод `Create`: форма → серверная проверка → параметризованный SQL → redirect.

### 3:30–4:30 — хранение и безопасность

Показать SQL-схему и связи users/expenses/categories/sessions. Объяснить целые копейки, bcrypt и HMAC токена. Во втором профиле браузера войти другим пользователем: история пуста, чужой ID возвращает 404.

### 4:30–5:20 — ошибки

Ввести отрицательную сумму: форма сохранена, ошибка понятна. Открыть отсутствующий маршрут: собственная 404. Показать тест восстановления после паники и JSON-лог запроса.

### 5:20–6:00 — запуск и результат

Показать `.env.example`, команды `go run .`, `go test ./...`, успешный CI. Объяснить, что база переживает перезапуск, контейнер работает без root, HTTPS обслуживает Caddy. Закончить демонстрацией опубликованного сайта.

## Ответы на частые вопросы

- **Почему GET не удаляет?** GET предназначен для чтения, его могут автоматически выполнять браузеры и поисковые роботы. Изменения проходят через POST и CSRF.
- **Почему не хранить пароль как SHA-256?** Обычный быстрый хэш ускоряет перебор. Bcrypt специально вычисляется медленнее и включает соль.
- **Почему сессии в БД?** Они переживают перезапуск, их можно отозвать; в памяти проще, но состояние теряется при остановке.
- **Зачем контекст?** Он передаёт проверенного пользователя и отмену запроса через цепочку без глобальной переменной.
- **Зачем буфер перед шаблоном?** Если шаблон завершится с ошибкой, можно вернуть цельный ответ 500, не отправив половину HTML.
- **Как работает `.env`?** Настройки загружаются при старте, процессное окружение имеет приоритет, обязательные параметры проверяются до запуска HTTP-сервера.
- **Что улучшать дальше?** Восстановление пароля по подтверждённому email, бюджеты, повторяющиеся расходы, персональные категории и отдельный limiter на уровне прокси. Эти функции не входят в обязательные этапы.
